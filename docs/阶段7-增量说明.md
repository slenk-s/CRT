# 阶段 7 · 前端交付说明（2026-10-08）

## 1. 目标与范围

在阶段 1–6（后端全部就绪、45 用例通过）之上交付**可用的前端**，覆盖：登录鉴权、转场记录列表、转场录入（移动端优先）、统一提交、转场详情与版本化更正、WB 参数查询、统计与管理端（字典/用户）。前端为独立 SPA，通过 `/api` 与后端对接，不改动后端任何代码。

## 2. 技术栈

| 项 | 选择 | 说明 |
|---|---|---|
| 框架 | Vue 3（`<script setup>`）+ TypeScript | 组合式 API，全量类型约束 |
| 构建 | Vite 5 | 开发态 `/api` 反代后端，免 CORS |
| UI | Element Plus 2.8（中文语言包） | 主色 `#409eff`，与《界面布局.html》一致 |
| 状态/路由 | Pinia + Vue Router 4 | token 持久化 + 登录/admin 双重守卫 |
| 图表 | 原生 SVG | 不引入 ECharts，包体更小、可控性更高 |
| 依赖 | 6 个运行时依赖 | 无自动导入插件，构建产物可预测 |

## 3. 交付内容

另新增后端**契约测试** `backend/tests/test_api_contract.py`：逐条复现前端发出的请求（路径、查询参数、multipart 字段名、`check_result` JSON 字符串、CSV BOM、batch/bom 互斥、401/403 边界、草稿删除），把前后端接口契约固化为回归测试。

## 4. 与后端契约的对齐要点

1. **勾选结果**：`check_result` 为 JSON 字符串（如 `{"光感":true}`），提交/更正均按此序列化。
2. **照片**：`<img>` 无法携带 `Authorization`，`photo_url`（形如 `/api/changeover/items/{id}/photo?ver=n`）统一经 `AuthImage` 用 axios 取回 Blob 展示，不暴露共享盘直链。
3. **统一提交**：允许部分提交；前端根据 `SubmitResult.failures[] / no_photo_items` 分场景回显「全部失败（仍为草稿）」「部分成功」，并列出每条失败原因。
4. **更正**：已提交记录走 `PUT`，后端生成 `ver+1`；详情页「版本历史」抽屉展示每个版本的照片、勾选、备注、更正说明与上传人。
5. **导出**：`GET /api/changeover/export.csv`，筛选参数与列表完全一致，UTF-8 BOM（Excel 直接打开不乱码）。
6. **首次改密**：`must_change_password=1` 时强制弹窗（不可关闭），改密成功后才可操作；管理员重置口令后同样生效。

## 6. 本地联调方法

```bash
# 1) 后端（内网环境直接连真实 SMB；本机演练可参考下方说明）
cd backend && uvicorn app.main:app --port 8000

# 2) 前端
cd frontend && npm install && npm run dev     # http://localhost:5173，/api 自动代理到 8000
```

> 若本机无内网 SMB：后端的 `get_storage` 依赖会在注入阶段返回 **503**（照片上传/归档不可用），这是设计上的降级行为，属于预期。本次浏览器实测用了一个仅存在于联调目录的「内存存储替身」覆盖该依赖（`e2e_app.py`），**不进入交付包**、不影响生产代码。

## 7. 部署

`npm run build` 后由 Nginx 托管 `dist/`，`/api` 反代后端（完整配置见 `frontend/README.md`）。要点：`try_files ... /index.html` 支持 history 路由回退；`client_max_body_size 20m` 允许照片上传。

## 8. 已知限制与后续

1. **照片上传依赖 SMB**：生产必须配置 `SMB_HOST / SMB_SHARE / SMB_USER / SMB_PASSWORD`，否则照片链路返回 503（前端已有明确提示）。
2. **前端压缩**：长边 >1920 或 >2MB 时压缩为 JPEG 0.85，GIF 与原图不压缩，直接透传。
3. **构建告警**：主 chunk ≈1.27MB（gzip 411KB），因 Element Plus 全量引入。若需进一步瘦身，可改为按需引入（`unplugin-vue-components`）或拆分 vendor chunk。
4. **待业务确认**：字典「检P1/检P2」检查项仍为空，需管理员在字典管理中补齐；WB 正式数据源接入方式待确认（当前 `WB_SOURCE=auto`）。
