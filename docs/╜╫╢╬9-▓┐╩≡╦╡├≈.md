# 阶段 9 · 部署说明（2026-10-08）

> 两态部署：**Windows 本机测试态**（快、适合产线旁试运行）与 **Linux 内网服务器态**（7×24 正式）。
> 同一套代码，只改 `.env` 与绑定地址。
> 本次已交付脚本 + 配置 + 文档；沙箱**无法访问内网 SMB/MES**，因此真实上线那一步需在目标机执行，本文给出逐条命令。

---

## 1. 部署形态与「前端由谁托管」

| 方案 | 前端托管 | 需要 Nginx | 访问地址 | 适用 |
|---|---|---|---|---|
| **A｜单端口**（默认，推荐） | 后端 FastAPI 直接托管 `frontend/dist` | ❌ 不需要 | `http://<host>:<端口>/` | 两态通用，最省事 |
| **B｜Nginx 反代** | Nginx 托管 dist，`/api` 反代后端 | ✅ 需要 | `http://<host>/` | 服务器已有 Nginx / 要走 80 端口 |

方案 A 的开启方式就是一句配置：

```ini
FRONTEND_DIST=/opt/changeover/frontend/dist   # Windows 例：D:/changeover/frontend/dist
SERVE_FRONTEND=auto                            # auto=有 index.html 才托管；off=仅 API
```

后端启动日志会打印 `[前端] 托管 /opt/changeover/frontend/dist`；此时 `/`、`/changeover/1`（history 深链）都会正确回 `index.html`，而 `/api/**` 仍由接口路由处理。

## 4. 方案 A-1｜Windows 本机测试态（最快上手）

```bat
:: 1) 环境准备（一次性；建 venv、装依赖、生成 .env、建库灌种子、自检、放行防火墙）
cd 产线转产管理轻应用\backend
scripts\deploy_windows.bat

::   ↑ 中途会自动弹出 notepad 让你填 .env，至少填这几项：
::     JWT_SECRET=（脚本已随机生成，可保留）
::     SMB_HOST=10.118.1.66   SMB_SHARE=pub   SMB_ROOT=slenk_\\FA_ROOT
::     SMB_USER=<专用服务账号>  SMB_PASSWORD=<口令>      ← 生产禁用匿名
::     SEED_ADMIN_EMP_ID=00660301  SEED_ADMIN_NAME=苏金炜  SEED_ADMIN_PASSWORD=<初始口令>

:: 2) 启动
scripts\start_backend.bat
```

访问：

- 本机：按 `start_backend.bat` 实际打印端口访问，例如 `http://127.0.0.1:8001/`
- 手机/平板（同局域网）：`http://<电脑IP>:<端口>/`（`ipconfig` 查 IPv4；若脚本不是 8001，请同步修改防火墙端口）

**开机自启（可选）**：右键管理员运行 `scripts\install_autostart_windows.bat`，用计划任务在开机时启动；卸载加 `remove` 参数。

> ⚠ 测试态局限：电脑睡眠/关机即不可用，不适合 7×24；草稿照片建议先落 `_test/` 根目录与正式归档隔离（见 `.env` 的 `SMB_ROOT`）。

## 5. 方案 A-2｜Linux 内网服务器态（正式）

### 5.1 一键部署（推荐）

```bash
# 把整个交付包拷到服务器（例如 /tmp/changeover），然后：
cd /tmp/changeover/backend
sudo bash scripts/deploy_linux.sh --dir /opt/changeover --user changeover --port 8000
```

脚本做的事（可重复执行，**不会覆盖已存在的 .env**）：

1. 创建 `changeover` 系统用户（禁用登录）
2. 复制代码到 `/opt/changeover`
3. 建 venv 并安装 `requirements.txt`
4. 生成 `.env`（随机 `JWT_SECRET`）并提示编辑
5. 建库 + 灌种子
6. 跑 `python -m app.preflight`
7. 打印访问地址与运维命令

### 5.2 手工部署

```bash
sudo mkdir -p /opt/changeover && sudo chown -R changeover:changeover /opt/changeover
cd /tmp/changeover
sudo cp -r backend frontend /opt/changeover/
sudo chown -R changeover:changeover /opt/changeover
cd /opt/changeover/backend

sudo -u changeover python3 -m venv .venv
sudo -u changeover ./.venv/bin/pip install -q --upgrade pip
sudo -u changeover ./.venv/bin/pip install -q -r requirements.txt

sudo cp .env.example .env
sudo vi .env     # 填 SMB_* / SEED_ADMIN_* / WB_* / MES_*
sudo chmod 600 .env

sudo -u changeover ./.venv/bin/python -m app.seed
sudo -u changeover ./.venv/bin/python -m app.preflight
sudo cp scripts/co.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now co co-maintenance.timer
```

访问：

- 本机：`http://127.0.0.1:8000/`
- 手机/平板：`http://<服务器IP>:8000/`

## 6. 方案 B｜Nginx 反代

适合已有 Nginx、或要把站点挂到 80 端口的服务器。

1. 后端 `.env` 改：`SERVE_FRONTEND=off`
2. 前端构建：`cd frontend && npm run build`
3. 复制配置：`backend/deploy/nginx-changeover.conf`
4. 语法检查：`sudo nginx -t`
5. 重载：`sudo systemctl reload nginx`

关键配置要点：

```nginx
server {
    listen 80;
    root /opt/changeover/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 20m;
    }
}
```

## 7. 日常运维

### 7.1 查看状态

```bash
sudo systemctl status co co-maintenance.timer
journalctl -u co -n 100 --no-pager
curl http://127.0.0.1:8000/api/health
```

### 7.2 重启 / 停止

```bash
sudo systemctl restart co
sudo systemctl stop co
```

### 7.3 每日维护

- `co-maintenance.timer`：每日 03:30
- 内容：SQLite `.backup` 在线备份 → 保留最近 N 份 → 草稿清理预演/执行

手动执行：

```bash
sudo -u changeover bash /opt/changeover/backend/scripts/maintenance.sh
```

### 7.4 草稿清理

```bash
# 预演（默认）：只打印将删除的草稿，不落库
cd /opt/changeover/backend && sudo -u changeover ./.venv/bin/python scripts/cleanup_drafts.py --dry-run

# 实际清理
sudo -u changeover ./.venv/bin/python scripts/cleanup_drafts.py
```

`DRAFT_TTL_DAYS` 控制未提交草稿保留天数，缺省 7 天。

## 8. 升级、回滚与 WB 集成

### 8.1 WB 数据源

- `WB_SOURCE=auto`：优先 `wb_mail.mes_api`，缺失时回退 HTTP 端点。
- `WB_SOURCE=mock`：用于前端联调。
- `WB_SOURCE=off`：关闭 WB 查询。

若使用 vendored `wb_mail`，在 `.env` 设置：

```ini
WB_MAIL_PATH=/opt/wb_mail
```

在交付文档中标注 `wb_mail` 的**版本号/提交号**，避免环境漂移。自检会报告 WB 数据源类型。

### 8.2 升级

```bash
sudo systemctl stop co
sudo cp -r <新包>/backend/app /opt/changeover/backend/
sudo cp -r <新包>/frontend/dist /opt/changeover/frontend/
cd /opt/changeover/backend && sudo -u changeover ./.venv/bin/pip install -q -r requirements.txt
sudo -u changeover ./.venv/bin/python -m app.preflight
sudo systemctl start co && curl http://127.0.0.1:8000/api/health
```

### 8.3 回滚

把上一版 `app/` 与 `dist/` 拷回；数据库如需回退用备份解压覆盖（**先停服**）。

## 9. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 无法登录 / 401「工号或口令错误」 | 未灌种子、或口令错、或库被重建 | 确认 `.env` 的 `SEED_ADMIN_*`；重跑 `python -m app.seed`；用 `sqlite3` 查 users 表 |
| 登录后强制改密弹窗无法关闭 | `must_change_password=1`（设计如此） | 输入原口令+新口令完成改密，或管理员重置 |
| 拍照上传 503 | `SMB_*` 未配 / 共享不可达 / 账号口令错 | 跑 `python -m app.preflight`；核对 `SMB_USER/PASSWORD`；确认服务器能访问 `\\10.118.1.66\pub` |
| 提交时报「草稿照片文件缺失」 | 草稿文件被清理或共享盘抖动 | 重新拍照再提交；查 `_draft/` 目录 |
| WB 查询 503「数据源未配置」 | `wb_mail` 未装/端点缺失 | `pip install -e /opt/wb_mail` 或设 `WB_BY_BATCH_URL`；先 `WB_SOURCE=mock` 联调前端 |
| 手机打不开页面 | 防火墙未放行 / 不同网段 | Windows：`netsh advfirewall firewall add rule ... localport=<实际端口>`；Linux：`firewall-cmd --add-port=<实际端口>/tcp`；确认 `APP_HOST=0.0.0.0` |
| 页面 404（刷新子路由） | 未开 SPA 托管且 Nginx 无 `try_files` | 方案 A：设 `FRONTEND_DIST`；方案 B：确认 `try_files $uri $uri/ /index.html` |
| 服务起来就退出（systemd 循环重启） | `.env` 语法错误 / 端口占用 / 权限 | `journalctl -u co -n 100`；确认 `ReadWritePaths` 含安装目录；按 `.env`/脚本实际端口检查监听，如 `ss -lntp | grep 8000` 或 `grep 8001` |
